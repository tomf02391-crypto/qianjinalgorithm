# 千金星轨 · PC28 · V9 真数据版

## 核心修复

### 问题诊断
上一版（V8）存在两个致命问题：
1. **数据接口解析错误** — `pc28.help` 的 `kj.json` 返回的 `num` 字段是特码字符串（如 `"15"`），前端 `split(",")` 后只有1个元素，被 `length<19` 判断跳过，**一条数据都解析不出来**
2. **GitHub Actions 被 Cloudflare 拦截** — 服务端 IP 访问 `pc28.help` 全部返回 403，降级到内置假数据（raw 里 17-19 个 0）

### V9 修复方案

| 问题 | 修复 |
|------|------|
| kj.json 特码解析 | 新增 `parseAnyFormat()` 自动识别 `number`/`num` 字段作为特码 |
| 无20码时三球缺失 | `decomposeSum()` 从特码反推最可能的三球组合（优先对子） |
| 服务端被 Cloudflare 封 | 前端 JS 直连（用户浏览器不在封锁列表） |
| 单接口失败即崩溃 | 5路容灾：pc28.help/kj → keno → yu28 → corsproxy → allorigins |
| 没有对错记录 | 新增 `updateRecords()` + 可视化圆点（绿=中/红=挂） |
| 倒计时精度 | 修正为 210 秒（3分30秒） |

## 接口格式说明

### pc28.help/kj.json（主要）
```json
{
  "countdown": "02:35",
  "data": [{
    "nbr": "3470331",
    "date": "2026-08-16",
    "time": "23:31:00",
    "number": "15",
    "num": "15",
    "combination": "大单"
  }],
  "message": "success"
}
```

```json
{
  "data": [{
    "nbr": "3470331",
    "date": "2026-08-16",

    "nums": [6,8,2,3,9,1,7,4,6,0,3,5,8,2,9,1,7,4,6,0]
  }]
}
```

## 算法

V9 使用六信号融合：
- EMA（权重3.0）
- 双EMA（权重2.0）
- 加权频率（权重2.5）
- 马尔可夫-1（权重2.0）
- 差分反转（权重1.5）
- 组合约束（权重1.2）
